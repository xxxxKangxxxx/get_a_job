# 공고 수집

`data/profile.md`의 조건으로 채용 사이트를 조사해 새 공고를 찾고, `pnpm postings:add`로 원본 JSON에 더한 뒤 `pnpm sync`로 앱 DB에 넣는다. 사용자는 앱의 "새 공고" 화면에서 지원할지 고른다.

## 준비

1. `data/profile.md`가 없으면 `pnpm init-data`를 실행하고, 사용자에게 조건을 채워 달라고 한 뒤 멈춘다. 예시 그대로인 상태(산업공학·구매 등)로 수집하지 않는다.
2. `data/profile.md`를 읽는다. 희망 직무, 적합도 A/B/C 기준, 고용 형태, 제외 조건, 기업 형태, 근무지, 조사할 사이트를 파악한다.
3. 이미 있는 공고를 확인한다. `data/postings.json`(경로는 `.env.local`의 `POSTINGS_JSON`이 있으면 그 값)의 `공고[]`에서 `기업명`+`공고명`과 `meta.회차`를 본다. 이미 있는 공고는 다시 넣지 않는다.

## 조사

- 조사 사이트(profile.md에 없으면 자소설닷컴·사람인·링커리어·잡코리아)에서 **지금 접수 중이거나 곧 열리는** 공고를 찾는다. WebSearch와 WebFetch를 쓴다.
- 희망 직무 이름과 그 동의어로 검색하고, 대기업·중견기업 공채 목록도 훑는다.
- 공고 상세 페이지를 열어 **사이트에 적힌 값만** 옮긴다. 모르는 칸은 비워 둔다. 추정값을 넣지 않는다(마감일·근무지·고용 형태를 짐작하지 않는다).
- 로그인이 필요하거나 막힌 페이지는 건너뛰고, 건너뛴 사실을 마지막에 알린다. 캡차를 풀거나 우회하지 않는다.
- 같은 공고가 여러 사이트에 있으면 하나로 합치고 `출처`에 사이트를 쉼표로 적는다. `링크`는 원 공고에 가장 가까운 것.

## 값 채우기

`/tmp/new_postings.json`(배열)에 쓴다. 칸 이름은 그대로 쓴다.

| 칸 | 규칙 |
|---|---|
| `기업명` `공고명` | 필수. 사이트 표기 그대로. 둘을 합친 것이 공고의 고유 키다 |
| `적합도` | 필수. profile.md의 A/B/C 기준으로 매긴다. 기준에 안 맞으면 넣지 않는다 |
| `직무분류` | 내 조건과 관련된 직무 위주로 짧게 (예: `구매·SCM`) |
| `기업형태` | `대기업` `중견기업` `외국계` `기타기업` 또는 빈 값. 판단 기준은 `data/postings.json`의 `meta.기업형태기준` |
| `기업형태근거` | `[집단] 그룹명` / `[검색] 확인한 곳` / `[규모] 매출·직원수` |
| `근무지` `고용형태` | 사이트 표기. 없으면 빈 값 |
| `접수시작` `접수마감` | `YYYY-MM-DD`. 상시·수시 채용이면 `접수마감`에 `"수시"` |
| `비고` | 여러 직무를 뽑으면 해당 직무만 한 줄로 (예: `모집직무 12개 중 해당: 구매, 물류`) |
| `출처` `링크` | 사이트 이름, 공고 주소 |

이미 있는 공고의 비어 있는 `근무지`를 알게 됐으면 `{"_근무지보강": true, "기업명": ..., "공고명": ..., "근무지": ...}`를 같은 배열에 넣는다.

## 넣기

```bash
pnpm postings:add /tmp/new_postings.json <이번 회차 = meta.회차 + 1>
```

오류가 나면 **아무것도 저장되지 않는다.** 오류를 고쳐 다시 실행한다. 성공하면:

```bash
pnpm sync
```

## 마무리

한두 줄로 알린다: 새 공고 몇 건(A/B/C별), 마감 임박(D-3 이내) 공고 이름, 건너뛴 사이트. 그리고 앱의 "새 공고" 화면에서 지원할지 고르면 된다고 안내한다. 공고 목록 전체를 채팅에 늘어놓지 않는다.
