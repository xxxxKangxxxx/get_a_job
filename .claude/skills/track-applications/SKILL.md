# 지원 기록

사용자가 말한 지원 상황을 `pnpm track`으로 앱 DB에 바로 기록한다. justdo 연동이 켜져 있으면 스크립트가 끝에 알아서 다시 보낸다.

## 말 → 동작

| 사용자 말 | 명령 |
|---|---|
| "대상 자재관리 쓸 거야" / "한국타이어 지원할 예정" | `plan` |
| "신한저축은행 지원했어" / "어제 제출함" | `apply` (`--date`로 지원일) |
| "서류 붙었어" / "떨어졌어" / "1차 면접 봤어" | `step --stage ...` |
| "서류 발표 9월 8일이래" / "면접 11/3 14시" | `step --date ... [--time ...]` |
| "영풍은 안 낼래" / "패스" | `skip` |
| "예정에서 빼줘" / "다시 살려줘" | `unplan` / `unskip` |

**아직 안 낸 것은 `plan`, 제출한 것은 `apply`다.** "쓸 거야·할 예정·후보"는 plan, "냈어·제출·지원했어"는 apply. 애매하면 제출했는지만 한 번 묻는다.

## 명령

```bash
pnpm track find <키워드>                       # 먼저 찾아보기
pnpm track plan <키워드> [--pick "공고명"]
pnpm track apply <키워드> [--pick "공고명"] [--date 2026-11-02]
pnpm track step <키워드> [--stage "서류 합격 · 1차면접 대기"] [--date 2026-11-10] [--time 14:00]
pnpm track skip|unplan|unskip <키워드>
```

- 키워드는 기업명이나 공고명 일부. 후보가 여럿이면 스크립트가 목록을 보여 준다. 그때만 사용자에게 어느 것인지 묻고 `--pick`으로 다시 실행한다.
- 날짜를 말하지 않았으면 지원일은 오늘이다(스크립트 기본값).
- `--stage` 값은 정해진 목록 중 하나여야 한다. 틀리면 스크립트가 가능한 값을 보여 준다.
  - 「…완료 · 결과 대기」 = 전형을 치렀고 결과를 모름. 「…합격 · … 대기」 = 합격하고 다음 전형을 기다림.
  - `불합격`(회사가 거름)과 `불참·포기`(본인이 안 감)를 구분한다.
- 트래커에 없는 공고면 지어내지 말고 알린다. 원하면 `collect-postings`로 공고를 먼저 넣거나, 앱에서 직접 추가하게 안내한다.

## 원칙

- 추가 질문을 하지 않는다. 기업명만 들어도 바로 기록한다.
- 사용자가 말한 것만 바꾼다. 결과를 추측하지 않는다("붙었어"라고 해야 합격).
- 끝나면 결과 한 줄만 알린다. plan이면 마감일을 같이 말한다.
