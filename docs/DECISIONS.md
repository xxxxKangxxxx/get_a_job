# 결정 기록

사용자와 정한 것. 모든 세션이 따른다. 새 결정은 총괄 세션만 추가한다(작업자는 Orca `ask`로 총괄에게 묻는다).

## 범위
- D1. 이력서·자소서 작성 기능은 넣지 않는다. 핵심은 **공고 일정 관리 + 오늘 무엇을 어디까지 할지 추천**.
- D2. 공고 수집은 지금처럼 Claude가 `/Users/kang-yeongmo/2026 취업하기/채용공고_데이터.json`에 하고, 앱은 동기화한다(원본은 읽기만). 직접 찾은 공고는 앱에서 추가한다.
- D3. 혼자 쓰는 앱. 로그인은 비밀번호 하나(`APP_PASSWORD`).

## 일정 계획
- D4. 남은 작업 시간을 하루 가용 시간 안에서 **마감 빠른 순**으로 배분, 마감 **1일 전** 완료 목표(설정 가능).
- D5. 기본 가용 시간: 평일 3시간, 주말 6시간, 공고 1건 기본 예상 4시간 (모두 설정에서 변경).
- D6. 시간이 모자라면 놓칠 공고와 해결책(포기 후보 / 특정 날 시간 늘리기)을 보여 주고 사용자가 고른다. **적합도 A는 포기 후보로 내지 않는다.** 포기 후보는 적합도 낮은 순(C→B), 같으면 남은 시간이 큰 것부터.
- D7. 면접은 3일 전부터 4시간, 인적성은 5일 전부터 5시간 준비 시간을 자동으로 잡는다.
- D8. 구글 캘린더 개인 일정(FreeBusy)만큼 그날 가용 시간을 줄인다.

## 구글 캘린더
- D9. 사용자는 구글 캘린더를 쓴다. 앱 전용 캘린더 "취업 일정"을 만들어 그 안에서만 생성·수정·삭제한다.
- D10. 캘린더 표시: 전형별 접수 기간(기본은 서류 접수 기간; 전형이 진행되면 현재 단계 일정만) + 작업 블록(시간대 배치, 계획이 바뀌면 재배치). **미결정 공고는 캘린더에 넣지 않는다.**

## 알림
- D11. 웹 푸시(PWA 홈 화면 추가). 아침 브리핑 + 마감 임박 + **미결정 A급 공고는 알림으로 "지원할까요?"** 결정 요청.

## 받은편지함
- D12. 수집된 새 공고는 받은편지함으로. 카드 한 장씩 넘기며 지원할래요/보류/관심 없음.
- D13. 관심 없음 이유(직무·지역·고용형태·기업규모·회사)를 고르면 숨김 규칙이 되어 비슷한 공고를 자동으로 숨긴다. 규칙은 설정에서 지울 수 있고, Claude 수집 조건으로 내보낼 수 있다.

## 디자인
- D14. 홈 = 오늘 할 일 중심, 분위기 = 친근한 모바일 앱형, 받은편지함 = 카드 한 장씩 넘기기.
- D15. 1차 시안(토스풍)은 "너무 별로" → 더 트렌디하고 고급스럽게. 레퍼런스 조사 후 방향 2~3개를 사용자에게 고르게 한다.

## 기술
- D16. Next.js 16 + Tailwind v4 + Drizzle + Neon(로컬은 PGlite) + Vercel. Supabase는 무료 한도 소진으로 쓰지 않는다.
- D17. 화면 ↔ 서버 약속은 `src/contracts/types.ts`, 함수는 `src/server/queries.ts`(읽기)·`src/server/actions.ts`(쓰기). 약속 변경은 총괄만.
